# Commit Convention

## Type

| Type | 설명 | 예시                                 |
| --- | --- |------------------------------------|
| `feat` | 새로운 기능 추가 | `feat: 게시글 작성 기능 추가`               |
| `fix` | 버그 수정 | `fix: 비밀번호 검증 오류 수정`               |
| `docs` | 문서 추가 또는 수정 | `docs: CONTRIBUTION.md 작성 가이드 추가`  |
| `refactor` | 기능 변경 없는 코드 구조 개선 | `refactor: 회원 서비스 로직 분리`           |
| `style` | 코드 포맷, 세미콜론, 공백 등 동작 변경 없는 수정 | `style: import 순서 정리`              |
| `test` | 테스트 코드 추가 또는 수정 | `test: 로그인 서비스 테스트 추가`             |
| `chore` | 빌드, 설정, 의존성, 기타 작업 | `chore: gradle 의존성 추가`             |
| `perf` | 성능 개선 | `perf: 게시글 목록 조회 쿼리 최적화`           |
| `ci` | CI/CD 설정 변경 | `ci: github actions 테스트 워크플로우 추가`  |

## Subject 작성 규칙
- 제목은 50자 이내로 간결하게 작성합니다.
- 마침표는 붙이지 않습니다.
- 무엇을 했는지보다 어떤 변경인지 드러나게 작성합니다.
- 한 커밋에는 하나의 목적만 담습니다.

좋은 예:

```text
feat: 이메일 인증 코드 발송 기능 추가
fix: 중복 닉네임 검증 조건 수정
refactor: 사용자 조회 로직을 서비스로 분리
```

피해야 할 예:

```text
fix: 수정
feat: 이것저것 추가
chore: 작업함.
```

## Body

제목만으로 설명이 부족하면 한 줄을 비우고 본문을 작성합니다.

```text
fix: 로그인 실패 시 응답 코드 수정

인증 실패 상황에서도 500 응답이 반환되던 문제를 401 응답으로 변경합니다.
클라이언트에서 실패 사유를 구분할 수 있도록 에러 메시지도 함께 정리합니다.
```

## Issue 연결

관련 이슈가 있다면 커밋 본문 또는 PR 설명에 이슈 번호를 연결합니다.

```text
feat: 프로필 이미지 업로드 기능 추가

Closes #12
```
