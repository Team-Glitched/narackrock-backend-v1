# 친구·팔로우·채팅 흐름

- 공개 프로필 팔로우는 즉시 `follows`에 저장한다. 비공개 프로필은 `follow_requests`에 대기 상태로 저장하고 대상 사용자만 승인하거나 거절할 수 있다.
- 맞팔로우는 양방향 `follows`가 모두 존재하는 관계다. 채팅받는 계정이 공개라면 보내는 계정의 공개 여부와 관계없이 팔로우 없이 메시지를 보낼 수 있다. 받는 계정이 비공개이면 맞팔로우가 필요하며, 조건을 충족하지 못하면 403을 반환한다. 공개 계정은 비공개 계정이 먼저 보낸 메시지를 읽을 수 있도록 자신의 대화 기록을 조회할 수 있지만, 맞팔로우 전에는 그 비공개 계정으로 답장을 보낼 수 없다.
- 추천은 같은 곡의 공동 작업자를 우선하고, 다음으로 친구의 친구를 보여준다. 후보가 없을 때는 인기 작곡가를 보여준다.
- 채팅 메시지는 DB에 저장하고 REST로 최근 50개를 조회한다. 전송은 REST를 유지하며 저장 완료 후 WebSocket으로 양쪽 사용자에게 새 메시지를 전달한다. 프론트엔드는 연결 중 WebSocket을 사용하고, 연결이 끊겼을 때만 3초 간격으로 조회한다.
- `GET /api/v1/chats`는 현재 사용자가 참여한 대화마다 마지막 메시지 하나를 최근 메시지 순으로 최대 100개 반환한다. 채팅 목록 화면은 이 결과를 위에 놓고, 아직 대화가 없는 맞팔로우 사용자를 그 아래에 표시한다. 공개 계정과 나눈 비맞팔 대화도 목록에서 유지한다.

## 웹소켓 확장

`/ws/chat` 연결 후 STOMP `CONNECT`의 `Authorization` 헤더로 기존 액세스 토큰을 검증한다. 브라우저의 URL 쿼리 문자열에 토큰을 넣지 않는다. 클라이언트는 인증된 사용자 전용 `/user/queue/chat`만 구독하며, 메시지 전송은 현재 `DirectChatUseCase.send`를 호출하는 REST API에서 처리한다. 클라이언트는 메시지 ID로 중복을 제거하고 재연결 시 REST 이력을 다시 조회한다. 현재 내장 브로커는 백엔드 단일 인스턴스용이며, 서버를 여러 대 운영할 경우 서버 간 전달을 추가해야 한다.

배포 환경에서는 `wss://<API 도메인>/ws/chat`이 백엔드 8080 포트로 전달되어야 한다. Nginx를 쓴다면 이 경로에 HTTP/1.1 `Upgrade`와 `Connection: upgrade` 헤더 전달 및 유휴 연결 제한 시간을 설정한다. `ADLIPS_CORS_ALLOWED_ORIGINS`에는 프론트의 정확한 출처(예: `https://narackrock.com`, 로컬 개발 시 `http://127.0.0.1:5173`)를 포함한다. Proxmox 자체 설정 변경은 필요하지 않지만, 실제 역방향 프록시 구성은 별도로 확인해야 한다.
