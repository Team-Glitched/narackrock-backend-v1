# 친구·팔로우·채팅 흐름

- 공개 프로필 팔로우는 즉시 `follows`에 저장한다. 비공개 프로필은 `follow_requests`에 대기 상태로 저장하고 대상 사용자만 승인하거나 거절할 수 있다.
- 맞팔로우는 양방향 `follows`가 모두 존재하는 관계다. 채팅 조회와 전송은 이 조건을 매번 확인한다. 한쪽이 팔로우를 해제하면 이후 메시지 조회와 전송을 차단한다.
- 추천은 같은 곡의 공동 작업자를 우선하고, 다음으로 친구의 친구를 보여준다. 후보가 없을 때는 인기 작곡가를 보여준다.
- 채팅 1차 구현은 DB에 메시지를 저장하고 REST로 최근 50개를 조회한다. 프론트엔드는 활성 화면에서 3초 간격으로 갱신한다.

## 웹소켓 확장

Spring WebSocket을 추가할 때 연결 인증에는 기존 액세스 토큰을 이용하되, URL 쿼리 문자열에 토큰을 넣지 않는다. 연결 후 첫 인증 프레임 또는 짧은 수명의 접속 티켓을 사용한다. 메시지 전송은 현재 `DirectChatUseCase.send`를 그대로 호출해 맞팔 권한을 다시 검사하고 DB에 저장한 뒤, 저장된 메시지 ID를 양쪽 사용자 채널에 전달한다. 클라이언트는 메시지 ID로 중복을 제거하고 재연결 시 REST 이력을 다시 조회한다. 서버를 여러 대 운영할 경우 Redis Pub/Sub로 서버 간 전달을 공유한다.
