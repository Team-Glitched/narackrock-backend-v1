# 숏폼 참여자 조회와 선택 재생

## API

두 API 모두 기존 Bearer 인증을 사용한다.

- `GET /api/v1/shorts/{shortId}/composers`: 기존 배열 계약을 유지한다. `userId`, `nickname`, `profileImageUrl`, `role`, `description`을 반환한다. 연결된 프로젝트의 승인되고 삭제되지 않은 트랙이 있으면 `role`은 해당 트랙의 악기 ID(예: `acoustic-guitar`)이며, 악기 없는 녹음·업로드 트랙은 `AUDIO`다. 여러 악기는 쉼표로 구분한다. 설명은 해당 참여자의 최신 승인된 참여 요청에서 가져온다. 연결된 트랙·참여 요청이 없는 기존 데이터는 저장된 역할·설명을 유지한다.
- `GET /api/v1/shorts/{shortId}/participant-tracks`: `{ shortId, project: { bpm, ppq, maxDurationMs }, tracks }`를 반환한다. 트랙·클립 구조는 작곡 트랙 조회의 읽기 DTO를 사용한다. 승인되고 삭제되지 않은 트랙과 클립만 포함하며, 오디오는 준비된 미디어의 URL, MIDI는 악기와 노트·타임라인을 전달한다. 멤버 가입이나 편집 권한 부여는 하지 않는다.

새 API는 기존 숏폼 공개 조회 규칙에 따라 공개된 진행 중 숏폼과 완료된 숏폼을 허용한다. 숏폼/연결 프로젝트가 없거나 삭제된 경우 404다. 작곡 편집 API를 호출하거나 ZIP을 다운로드할 필요가 없다. DB 스키마 변경은 없다.

## 프론트엔드 동작

- 처음에는 전체 참여자가 체크된다. 같은 곡의 패널을 다시 열면 현재 선택을 유지한다.
- 닫기 버튼, 배경, Escape, 아래로 핸들 스와이프, 하단 버튼으로 닫을 때 선택을 적용한다.
- 전체 선택이면 기존 믹스 파일을 그대로 재생한다. 일부 선택이면 참여자 트랙 API를 한 번 로드하고 `track.ownerId`로 필터링한다. 모두 해제하면 재생을 멈춘다.
- 선택 재생은 현재 곡 위치에서 이어지며 원곡 길이를 유지한다. MIDI와 오디오를 하나의 Web Audio 시계로 예약하고 트랙 볼륨·팬·음소거·솔로, 오디오 트림과 클립 시작 위치를 반영한다. MIDI는 작곡 화면과 같은 악기 카탈로그·샘플을 사용한다.
- 패널을 닫아도 선택 재생을 유지한다. `전체 듣기` 또는 전체 선택으로 기존 믹스로 복귀한다.
- 일시정지·탐색·음소거·반복/다음 곡 설정을 지원한다. 곡 전환과 화면 이탈 시 예약된 음원과 진행 중 요청을 취소한다.

## 검증

백엔드: `./gradlew test` (참여자 메타데이터, API 인증·404, 승인 데이터 조회, 기존 숏폼 공개 조회 정책 포함).

프론트엔드: `npm test`, `npx tsc --noEmit`, 변경 파일 ESLint, `npm run build`. 모의 API를 사용하는 로컬 브라우저 검증에서는 패널 높이·기본 선택·선택 유지·선택 재생·전체 복귀·모두 해제·곡 전환을 확인한다.
